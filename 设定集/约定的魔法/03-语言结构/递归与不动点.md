# 递归与不动点

约定将用于建立递归不动点的算子称为“闭合”。其语义已经确定，具体符文字形尚待收入符文表。

## 自我引用问题

算子只有在成型以后才会产生引用。因此，施法者在构造一条计算关系时，不能预先取得尚未形成的最终引用，再把它作为自身的输入。普通的直接自我引用在书写顺序上无法成立。

然而，纯计算层需要能够表达递归。约定中因此存在“闭合”算子，用于把规则引用中的自我输入与最终结果接合起来。

## 基本关系

设规则引用 `F` 的签名为：

```text
F : [自身, P₁, …, Pₙ] → R
```

“闭合”把第一个空缺作为自我输入，产生签名为 `[P₁, …, Pₙ] → R` 的引用 `X`，并使二者满足：

```text
X = F(X)
```

这里的等式不是把某个结果预先算出并保存，而是说明：每当计算关系需要递归调用时，它所使用的第一个参数就是最终形成的引用 `X` 自身。由此，原本无法在书写期间直接取得的自我引用被闭合起来。

如果 `F` 在自我输入之后仍有其他空缺，`X` 就是一个保留这些空缺的规则引用。例如，一个以自身和数值 `n` 为参数的规则，闭合后会得到只等待 `n` 的递归规则。有效闭合要求“自身”空缺能够接受这个闭合后的 `X`；也就是说，它必须接受具有剩余签名 `[P₁, …, Pₙ] → R` 的引用。

## 惰性展开

闭合不会在算子成型时把递归过程全部执行一遍。它只形成新的引用关系；递归所需的部分仍在引用被实际取值时才展开，并服从纯计算层通常的惰性取值规则。

若取值能够在有限展开后到达终止条件，高维执行机制可以得到相应结果。若被实际需要的递归永不终止，依赖该结果的指令便无法执行。与任何指令都无关的无限递归则不需要取得结果，也不会单独产生世界效果。

## 不产生存储

自我引用不等于内部存储。闭合所得引用不会保存上一次递归的中间值，也不会在多次取值之间保留状态。每次取值仍以该瞬间的世界和最终指令句提供的坐标上下文重新计算。

若 `F` 不实现规则接口、没有任何空缺，或第一个空缺不能接受闭合后所得 `X` 的接口与签名，闭合会直接失败。闭合的完整算子条目参见[闭合](../06-符文参考/算子/闭合.md)。
