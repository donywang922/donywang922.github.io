# 规则引用

## 悬置算子

通常情况下，算子书写完成时会读取规定位置上的输入引用，并立即产生结果引用。但“没有取得全部输入”和“输入错误”是两种不同情况。

一个字形正确、已有输入也符合接口要求，却仍有至少一个输入位置为空的算子，称为**悬置算子**。它已经书写完成，但不会成型，不产生引用，也不发生献祭。悬置不是失败；算子的结构和空缺输入位置仍可被之后的操作使用。

如果算子字形错误，或某个已经放入的引用不满足对应接口，算子仍按通常规则直接失败。失败算子不能被当作悬置算子封装，也不能通过之后补入其他引用得到补救。

## 封装

“封装”算子作用于一个悬置算子，把它转换成**规则引用**。规则引用保留三类信息：

- 原算子的种类；
- 已经绑定的输入引用；
- 尚未填入的输入位置及其固定顺序和接口要求。

封装保存的是关系，不是取值。已经绑定的输入仍然是原引用；如果它们指向的现实对象后来发生变化，规则引用在实际取值时仍会读取变化后的世界。

悬置算子此前没有成型，也没有单独献祭。封装成功时，悬置算子的书写时空与封装算子自身的书写时空共同构成规则引用的成型献祭。参与两段书写的人，以及已绑定输入引用原有的施法者，都会进入新规则引用的构成历史。

## 规则接口

规则引用实现“规则”接口。该接口公开一个有序的空缺输入表，称为规则的**签名**。签名记录每个空缺要求的接口，并记录全部空缺补齐后所得结果能够实现的接口。

空缺的顺序由原算子输入位置的固有顺序决定，不随施法者拖入引用的先后次序改变。具体符文中的空间排列由各算子页面分别说明。

规则引用可以像其他引用一样被拖动、复制并作为算子的输入，也可以成为另一个规则计算出的结果。因此，规则本身属于可以被引用和组合的概念。

## 补全

“补全”算子接受一个规则引用和一个参数引用，并把参数绑定到规则签名中的第一个空缺。

若参数不满足该空缺的接口要求，补全直接失败。若绑定后仍有空缺，补全产生一个新的规则引用；若最后一个空缺也被补齐，补全产生原算子所规定的结果引用。

补全不会修改原规则引用，也不会把参数当时的取值保存下来。新引用只记录新的绑定关系。由此，向多输入规则依次补入参数的过程可以逐步进行，而各阶段的规则引用仍可分别保留和复用。

## 高阶规则

规则引用既是规则，也是引用。因此，规则可以接收其他规则，或产生新的规则引用。这种结构称为高阶规则。

高阶规则不引入第二套执行机制。无论嵌套多少层，全部结构仍只是惰性的引用关系；只有最终被指令句实际要求取值的部分才会展开。规则引用自身没有输出和保存计算结果的能力。

## 判定摘要

| 书写完成时的状态 | 结果 |
| --- | --- |
| 字形正确、所有输入齐全且接口相符 | 正常成型并产生结果引用 |
| 字形正确、已有输入相符、仍有输入缺失 | 成为悬置算子，不成型、不献祭 |
| 字形错误 | 直接失败 |
| 已放入的输入接口不符 | 直接失败 |
| 封装一个悬置算子 | 产生规则引用，并献祭悬置算子与封装算子的书写时空 |

规则引用的递归闭合参见[递归与不动点](递归与不动点.md)，其计算能力参见[计算完备性](计算完备性.md)。
